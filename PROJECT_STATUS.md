# Статус проекта DevOps LLM Agent

_Обновлено: 2025-09-29_

## Краткое резюме
Проект находится в стадии раннего каркаса. Реализованы базовые классы агентов, маршрутизатор LLM с локальным детерминированным провайдером и FastAPI-приложение, но большинство интеграций (реальные LLM, исполнители команд, БД, UI) не подключены и не покрыты тестами. Поставлена минимальная регрессия: несколько unit- и интеграционных тестов проверяют настройки и поведение оркестратора с локальным провайдером.

## Что работает
- Оркестратор и агенты (planner/executor/verifier) возвращают ответы, используя локальный LLM-провайдер (`local`), доступный по умолчанию в `config/llm.yml`.
- FastAPI-приложение и зависимости загружают конфигурацию через `config/settings.py`, валидируют профили окружений при помощи `packages.shared.env_schema`.
- Репозиторий приведён к базовой гигиене: добавлен `.gitignore`, make-таргет `clean` удаляет артефакты, удалены закоммиченные venv/node_modules/.next.
- Существуют каркасы SSH/Kubectl/Docker executors, политик безопасности, observability и UI, однако они не подтверждены в работе.

## Критические пробелы
- **LLM**: интеграции с Gemini/Ollama отключены; нет тестов/фоллбеков для реальных API, не управляются секреты.
- **Инфраструктурные исполнители**: классы есть, но нет локальных заглушек, интеграционных тестов и проверок окружения (asyncssh/kubectl/docker).
- **API/БД/Аутентификация**: в коде предусмотрены зависимости на БД, JWT и пр., но рабочие миграции, репозитории, провайдеры данных не настраивались.
- **Web UI**: каталоги есть, но зависимости не установлены, сборка и интеграция с API не проверялись.
- **Наблюдаемость и безопасность**: конфигурации декларативны, фактических интеграций (Prometheus, audit logging, sandboxing) нет.
