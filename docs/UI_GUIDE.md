# Руководство по использованию Web UI

## Обзор

Web UI для DevOps LLM Agent предоставляет полноценный интерфейс для управления агентами, мониторинга задач, тестирования и настройки системы.

## Основные возможности

### 1. Чат с агентом (💬 Chat)

Основной интерфейс для взаимодействия с DevOps агентом:

- **Отправка команд**: Введите задачу в текстовое поле и нажмите кнопку отправки
- **Выбор окружения**: Выберите целевое окружение из выпадающего списка в header
- **Мониторинг задач**: Правая панель показывает активные задачи в реальном времени
- **История чата**: Все сообщения сохраняются в сессии

Примеры команд:
```
- Проверить статус всех подов в namespace default
- Развернуть nginx в кластере
- Показать логи пода webapp-12345
- Масштабировать deployment до 3 реплик
```

### 2. Настройки системы (⚙️ Settings)

Панель управления и мониторинга системных компонентов:

#### Вкладка "Система"
- **Версия системы**: Текущая версия API
- **Статус компонентов**: 
  - LLM Провайдеры (доступность и здоровье)
  - Redis (подключение и статус)
  - База данных (подключение)
- **Включенные функции**: Список активированных возможностей системы

#### Вкладка "LLM Провайдеры"
- **Статус провайдеров**: Онлайн/Офлайн статус для каждого провайдера
- **Конфигурация**:
  - Тип провайдера (Gemini, Ollama, Local)
  - Статус включения/отключения
  - Приоритет
  - Доступные модели

#### Вкладка "Кеш"
- **Статистика кеша**:
  - Количество попаданий (hits)
  - Количество промахов (misses)
  - Детальная статистика
- **Управление**: Кнопка "Очистить кеш" для сброса кеша

#### Вкладка "База данных"
- **Статус подключения**: PostgreSQL connection status
- **Информация о здоровье**: Индикатор работоспособности БД

### 3. Тестирование агентов (🧪 Testing)

Инструмент для тестирования и отладки работы агентов:

#### Настройки тестирования
- **Задача**: Введите текст задачи для тестирования
- **Окружение**: Выберите целевое окружение (опционально)
- **Тип агента**: 
  - Planner (Планировщик) - планирует выполнение задачи
  - Executor (Исполнитель) - выполняет команды
  - Verifier (Проверяльщик) - проверяет результаты
- **Автоматическое подтверждение**: Включите для автоматического одобрения задач

#### Результаты тестов
- **Test ID**: Уникальный идентификатор теста
- **Статус**: Success/Failed
- **Время выполнения**: Длительность теста в секундах
- **Результат**: Детальный JSON с результатами выполнения
- **Ошибки**: Информация об ошибках, если они возникли

### 4. Просмотр Workflow (🌿 Workflow)

Детальный просмотр выполнения задач и аудит логов:

#### Информация о задаче
- **Task ID**: Идентификатор задачи
- **Статус**: Текущий статус выполнения
- **Время создания/обновления**: Timestamps

#### Шаги Workflow
- **Визуализация шагов**: Раскрывающиеся блоки для каждого шага
- **Статус каждого шага**: Pending/In Progress/Completed/Failed
- **Детали шага**: JSON данные о выполнении шага

#### Результаты выполнения
- **Agent**: Какой агент выполнял шаг
- **Message**: Сообщение о результате
- **Metadata**: Дополнительные метаданные
- **Errors**: Ошибки, если были

#### Журнал аудита
- **Timestamp**: Время события
- **Action**: Выполненное действие
- **Details**: Детали события
- **User ID**: Пользователь, инициировавший действие

## Навигация

### Левая панель (Вертикальное меню)
- 💬 **Chat**: Интерфейс чата с агентом
- ⚙️ **Settings**: Настройки и мониторинг системы
- 🧪 **Testing**: Тестирование агентов
- 🌿 **Workflow**: Просмотр workflow и логов

### Header
- **Menu**: Открыть мобильное меню (на малых экранах)
- **Environment Selector**: Выбор текущего окружения
- **User Info**: Информация о пользователе (если авторизован)

### Правая панель
- **Task Monitor** (в режиме Chat): Мониторинг активных задач
- **Task List** (в режиме Workflow): Список задач для просмотра

## Запуск UI

### Development режим

1. Установите зависимости:
```bash
cd apps/ui
npm install
```

2. Настройте переменные окружения:
```bash
# Создайте .env.local файл
NEXT_PUBLIC_API_BASE_URL=http://localhost:8000
```

3. Запустите dev server:
```bash
npm run dev
```

4. Откройте браузер: http://localhost:3000

### Production режим

1. Соберите приложение:
```bash
cd apps/ui
npm run build
```

2. Запустите production server:
```bash
npm start
```

Или используйте Docker:
```bash
docker build -f apps/ui/Dockerfile -t devops-agent-ui .
docker run -p 3000:3000 -e NEXT_PUBLIC_API_BASE_URL=http://api:8000 devops-agent-ui
```

## Требования

### Backend API
Убедитесь, что API сервер запущен на порту 8000:
```bash
# Из корневой директории проекта
make bootstrap
python -m uvicorn apps.api.main:app --reload --port 8000
```

### Зависимости
- Node.js >= 18.x
- npm >= 9.x
- React 18+
- Next.js 14+

## Функции в реальном времени

### Автообновление
- **Task Monitor**: Обновляется каждые 3 секунды
- **Workflow Viewer**: Кнопка "Обновить" для manual refresh
- **Settings Panel**: Кнопка "Обновить" для обновления статуса системы

### WebSocket (планируется)
В будущих версиях будет добавлена WebSocket поддержка для:
- Реального времени обновления статусов задач
- Push уведомлений о завершении задач
- Streaming ответов от LLM

## Troubleshooting

### UI не подключается к API
- Проверьте, что API запущен: `curl http://localhost:8000/health`
- Проверьте CORS настройки в `apps/api/main.py`
- Проверьте `NEXT_PUBLIC_API_BASE_URL` в .env.local

### Ошибки загрузки данных
- Откройте Developer Console (F12)
- Проверьте Network tab для failed requests
- Убедитесь, что все endpoints доступны

### TypeScript ошибки
- Выполните `npm install` для установки всех зависимостей
- Проверьте версию Node.js: `node --version`
- Очистите кеш: `rm -rf node_modules .next && npm install`

## Безопасность

### Аутентификация
- JWT токены хранятся в localStorage
- Токен автоматически добавляется в заголовки запросов
- При 401 ошибке происходит редирект на /login

### CORS
- Настройте allowed origins в production
- Не используйте `allow_origins=["*"]` в production
